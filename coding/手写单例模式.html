恶汉式单例

特点：占用内存

public class Hungry{
  //1.构造器私有
  private Hungry(){}
  //2.静态私有实例
  private static Hungry HUNGRY = new Hungry();
  //3.返回静态实例的方法(公共，静态)
  public static Hungry getInstance(){
    return HUNGRY;
  } 
}

懒汉式

特点：省内存，但线程不安全

public class LazyMan(){
  //1.构造器私有
  private LazyMan(){}
  //2.空的静态实例
  private static LazyMan LAZYMAN = null;
  //3.返回实例的方法：判断为空，构造一个对象，返回对象
  public static LazyMan getInstance(){
     if(LAZYMAN == null){
       LAZYMAN = new LazyMan();
     }
     return LAZYMAN;
  }
}

双重检测锁模式

特点：线程安全，但是会被反射破解

public class Singleton{
  //1.构造器私有
  private Singleton(){}
  //2.空的静态实例，配上volatile，保证可见性
  private static volatile Singleton singleton = null;
  //3.返回实例的方法：先判断是为空的话，锁上类，再判断是否为空，如果为空，构造一个对象，最后返回对象
  public static Singleton getSingleton(){
    if(singleton == null){
      //上类锁
      synchronized(Singleton.class){
        //双重检测，可能上锁期间，其他线程早就已经给空实例给填充好了
        if(singleton == null){
          singleton = new Singleton();
        }
      }
    }
    return singleton;
  }
}

反射破解双重检测锁

public static void main(String[] args) throws Exception {
    //获取原来的单例
    Singleton singleton1 = Singleton.getSingleton();
    //通过反射获取构造函数
    Constructor<Singleton> declaredConstructor = Singleton.class.getDeclaredConstructor();
    //设置访问权限，破坏私有访问
    declaredConstructor.setAccessible(true);
    //通过构造器获取一个新的实例
    Singleton singleton2 = declaredConstructor.newInstance();

为什么能破解呢？

因为只要不调用getSingleton(),那么singleton永远为null，所以永远不会抛出异常。

那么可不可以，修改构造方法，使其，只可能构造一次呢？答案是有的，打标记法。

修改双重检测代码2

public class Singleton {
    //打标志，使其只能构造一次
    private static boolean flag = false;
    //1.构造器私有
    private Singleton() {
        synchronized (Singleton.class) {
            if (flag == true) {
                throw new RuntimeException("不要试图用反射破坏单例");
            }
            flag = true;
        }
    }

    //2.空的静态实例，配上volatile，保证可见性
    private static Singleton singleton = null;

    //3.返回实例的方法：先判断是为空的话，锁上类，再判断是否为空，如果为空，构造一个对象，最后返回对象
    public static Singleton getSingleton() {
        if (singleton == null) {
            //上类锁
            synchronized (Singleton.class) {
                //双重检测，可能上锁期间，其他线程早就已经给空实例给填充好了
                if (singleton == null) {
                    singleton = new Singleton();
                }
            }
        }
        return singleton;
    }
}

枚举单例法

既然双重检测锁总是被破解，那么有没有一种方法，可以阻止反射破解的呢？

分析

通过反射破解，最终都是通过获取构造器,然后调用newInstance()方法。 那么，我们可以看看这个方法的源码。 那么，枚举类，就是我们的突破口。

枚举本身是个类型本身就是单例

public enum EnumSingle {
    INSTANCE;

    public EnumSingle getInstance(){
        return INSTANCE;
    }
    
    public static void main(String[] args) {
        EnumSingle instance1 = EnumSingle.INSTANCE;
        EnumSingle instance2 = EnumSingle.INSTANCE;
        System.out.println(instance1 == instance2); //true
    }
}

枚举单例写法

public class EnumSingleton {

    private enum SingletonEnum{
        INSTANCE;

        private EnumSingleton instance;
        private SingletonEnum(){
            instance = new EnumSingleton();
        }
        
        private EnumSingleton getInstance(){
            return instance;
        }
    }
    
    public static EnumSingleton getInstance(){
        return SingletonEnum.INSTANCE.getInstance();
    }

}
