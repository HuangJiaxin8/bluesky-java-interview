# Dubbo

## Dubbo 和 Spring Cloud 有什么关系？

- Dubbo 是 SOA 时代的产物，它的关注点主要在于服务的调用，流量分发、流量监控和熔断。
- 而 Spring Cloud 诞生于微服务架构时代，考虑的是微服务治理的方方面面。它为微服务提供一系列的解决方案。


## Dubbo 有哪些注册中心？

- Zookeeper 推荐
- Redis
- Nacos


##  Dubbo 的注册中心集群挂掉，发布者和订阅者之间还能通信么？

- 可以通讯。启动 Dubbo 时，消费者会从注册中心拉取生产者的地址接口数据，缓存在本地。每次调用时，从本地缓存拿地址信息就行了。

## Dubbo的缓存机制

- Dubbo提供了服务端和客户端的缓存机制
- 服务端：把方法的放回值缓存到内存中，提供了三种缓存方式：
	- LRU
	- ThreadLocal
	- Concurrent Map
- 客户端：
	- 把响应的结果存到内存中，提供了两种缓存方式
		- LRU
		- ThreadLocal


## Dubbo 如何实现像本地方法调用远程方法的

- 动态代理，使用了JDK动态代理和字节码增强技术，生成了代理类。
	- 代理类实现了本地接口，具有本地接口的所有方法，调用本地接口方法时，会通过代理类的invoke方法把请求转发到远程的服务提供者上。
- 网络通信，走网络肯定要序列化反序列化。
- 远程调用执行，服务端接收到请求后，会根据请求的服务接口名和方法名找到对应的实现类和方法，将请求消息反序列化成方法参数，最终执行服务提供者的方法，把结果序列化后响应给客户端。


## Dubbo 服务调用是阻塞的吗？

默认是阻塞的，可以异步调用，没有返回值的可以这么做。


## Dubbo 服务器注册与发现的流程？

- 服务容器 Container 负责启动，加载，运行服务提供者。
- 服务提供者 Provider 在启动时，向注册中心注册自己提供的服务。
- 服务消费者 Consumer 在启动时，向注册中心订阅自己所需的服务。
- 注册中心 Registry 返回服务提供者地址列表给消费者，如果有变更，注册中心将基于长连接推送变更数据给消费者。
- 服务消费者 Consumer，从提供者地址列表中，基于软负载均衡算法，选一台提供者进行 调用，如果调用失败，再选另一台调用。
- 服务消费者 Consumer 和提供者 Provider，在内存中累计调用次数和调用时间，定时每分钟发送一次统计数据到监控中心 Monitor。


## Dubbo 集群提供了哪些负载均衡策略？

- 轮询
- 随机
- 加权随机
- 最小活跃


## Dubbo支持哪些序列化方法？

- 标准java序列化协议
- fastjson2
- Hessian2 默认


## Dubbo 支持哪些协议

- dubbo协议（默认）
- rmi协议 （jdk标准）
- hessian协议
- http协议
- webservicce协议
- thrift协议
- memcached协议
- redis协议
- restful协议


## 服务发现与路由的区别

- 服务发现是获取服务提供者的地址信息
- 路由是把服务请求到指定的服务提供者上



## 优雅停机

Java.Runtime.addShutdownHook(Thread hook)方法，可以注册一个JVM关闭的钩子
