## JWT（JSON Web Token）

- 服务器端不需要保存 `Session` 数据，只需要客户端保存服务端返回的token,
- JWT 由 3 部分构成:
    - Header（JWT头） : 描述 JWT 的元数据，定义了生成签名的算法以及 Token 的类型。
        - {"alg": "HS256","typ": "JWT"}
    - Payload （有效载荷）: 用来存放实际需要传递的数据
    - Signature（签名） ：服务器通过Payload、Header和一个密钥(secret)使用 Header 里面指定的签名算法（默认是 HMAC SHA256，简称HS256）生成。
        - 可选算法：
            - 默认HS256，对称加密
            - RS256,使用RSA算法，是非对称加密


## jwt如何进行身份验证

- 服务器通过Payload、Header和一个密钥(secret)创建令牌（Token）并将 Token 发送给客户端，客户端将 Token 保存在 Cookie 或者 localStorage 里面，以后客户端发出的所有请求都会携带这个令牌。
- 你可以把它放在 Cookie 里面自动发送，但是这样不能跨域，所以更好的做法是放在 HTTP Header 的 Authorization 字段中。
- 大概过程：
    - 客户端登录账号密码登录服务器
    - 服务器验证身份，返回token
    - 客户端保存token，下一次访问服务端带上token
    - 服务的根据token判断客户身份

## OAuth 2.0

[认证授权基础 | JavaGuide](https://javaguide.cn/system-design/security/basis-of-authority-certification/#%E4%BB%80%E4%B9%88%E6%98%AF-oauth-2-0)

- 是一种授权机制，它的最终目的是为第三方应用颁发一个有时效性的令牌 Token，使得第三方应用能够通过该令牌获取相关的资源。
- OAuth 2.0 比较常用的场景就是**第三方登录**，当你的网站接入了第三方登录的时候一般就是使用的 OAuth 2.0 协议。


## MD5 加盐和不加盐 有什么区别？

- 不加盐的话，相同密码md5后的值是一样的，那么很有可能被暴力破解
- 加了盐之后，更安全了，因为还要再猜盐的值是多少



## 对称加密和非堆成加密有什么区别？

- 对称加密用的是同一个密钥
- 非对称加密用到了公钥和私钥，公钥一般要去CA机构去获取证书存储到本地。私钥加密的话，公钥解密。公钥加密的话，私钥解密。
